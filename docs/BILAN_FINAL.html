Glossary

AI agents
Artificial-intelligence programs that played the role of auditors. They belong to the same team: this is not a human or external review.
audit round
One pass of checks by three independent auditors: the server, the student journey in a real browser, the teacher view and the documents.
backend (server)
The invisible part of the application. It computes score, time, hints and unlocks: it is the authority.
Code Vault
The screen where a laboratory's exit code is entered once its fragments are found.
connection cap
A limit on the number of simultaneous visitors. It does not exist yet: to add before any public exposure.
Content review
The screen that tracks the review of the content. Every mission is "Draft" there: the content has not been reviewed by experts.
DEMO-READY ACADEMIC MVP
The official wording: an academic prototype ready to be shown. It says nothing about scientific validity.
end-to-end (e2e)
A test that walks through the whole application, from screen to server, like a user.
ESCALATE
Status meaning "must be escalated": until human reviews (security, accessibility, biomedical) are done, going to production is not allowed.
Faculty
The teacher view of the application.
fragments
Pieces of the exit code earned by succeeding at missions.
fresh database (seed:demo)
A command that fills a database with generated demonstration data (38 fictitious students).
frontend (interface)
The part shown in the browser. It only displays what the server decides.
IPv6
The modern Internet address format. One computer can use a huge number of them, which defeats a per-address cap.
JS / CSS
The two main kinds of site files: JS = the program, CSS = the styling.
Master Lab
The final laboratory, unlocked when three laboratories are completed.
mutation test
The code is deliberately broken to check that a test notices. If the test stays green, it is useless.
Node 22
The version of the engine that runs the server.
npm audit
A check for already-known security flaws in the software libraries in use.
OpenAPI
The document that officially describes every request the server accepts. "Unchanged" means the server's contract did not change.
P0
Critical defect: data loss, security hole, unusable application.
P1
Blocking defect: wrong score or progression, broken mission, essential feature inaccessible, frozen server.
P2 / P3
Less serious defects (annoyance, polish, wording). They do not block the demonstration unless they disturb it.
Playwright
A tool that drives a real browser the way a person would: clicks, keyboard, simulated phone.
ports 3000 and 5173
The "doors" of the server and of the test site on your computer. Playwright needs both and cannot run while you are testing.
production bundle
The set of files actually sent to the browser. A size limit keeps the site fast.
quadratic
A computation whose duration explodes: it is multiplied by 4 when the data doubles. With a lot of data, a single account could freeze the server for everyone.
rate limiter
A cap on the number of allowed requests, to prevent abuse.
remote CI (continuous integration)
Automatic execution of the tests on a remote machine. There is none here: everything was checked on one computer.
S-1
The name given to the one P1 that remains open: the Blood Smear Code mission has no path usable without sight.
schistocyte
A fragment of a red blood cell, to be spotted on the mission's smear.
screen reader
Software that reads the screen aloud for blind or low-vision people.
snapshot
A unique fingerprint (a string of characters) computed over all code and test files. If a single file changes, the fingerprint changes. It stands in for a version number because there is no Git here.
text alternative
A text that gives the same information as an image, so everyone can access it.
typecheck
An automatic check that the code is consistent before it is even run.
Vitest
An automatic test tool for the interface (frontend).
XP
The game's experience points.
