# Known limitations and deliberate decisions

Status date: 2026-10-09 (first written 2026-10-07; notes added after adversarial rounds 10 to 17, 20 to 23 and 34 to 39 (the last six are the sections "Round 34 notes" to "Round 39 notes" at the end); the content pointer and items 10-14 date from 2026-10-09). These are things the code does on purpose, or does not yet do, that a reviewer must know about. None of them is hidden by a test.

## Product decisions (need an owner's confirmation)

1. **Order and match give a partial signal.** A wrong answer on an `order` or `match` step returns `progress: {correct, total}` ("3 of 5 in place"). It never states the key, but repeated tries can narrow it down: an adversarial simulation solved a 5-item order in ~5 guesses on average (blind guessing: ~60). Each wrong try costs XP and the answer endpoint is rate limited (120/min/student), but there is no attempt cap. Least invasive mitigation if wanted: return `progress` only on the first wrong answer per step (the frontend normalizer already accepts `null`).
2. **Point (hotspot) steps can be brute forced** at a -10 XP penalty per miss; there is no distance feedback.
3. **A single teacher can review and approve the same mission.** There is no four-eyes rule because the one-teacher demo flow would break. Every transition is recorded in the append-only `content_audit` table with the actor, so a stricter rule can be added later without losing history.
4. **Content approval is keyed by mission id, not by content.** Editing `be/src/content.ts` does not reset an `approved` mission to `draft`. Storing a content hash at review time would fix this.

5. **All guests share one server user (needs the owner's decision, P1 in the browser audit VA-01).** `POST /auth/demo` always signs in the seeded demo student "Alex Martin" (the Faculty roster lists the same person). Consequences: progress, XP and attempts are shared between simultaneous visitors; one visitor's `Reset guest session` (or `POST /demo/reset`) deletes another visitor's in-flight attempt, which the UI then reports as "This case is no longer available" with a Restart action; a brand-new visitor sees prepared demo progress (level 6, 8,240 XP) rather than an empty start. The dashboard now says that this is demonstration data. A per-visitor sandbox (one throw-away student per guest session, starting empty or cloned from the demo story) is a larger change: the Playwright end-to-end tests rely on the single seeded guest. Decide before any public demo with concurrent visitors.
6. **The leaderboard is platform-wide on request.** `GET /leaderboard?cohort=all` lists every student (short name, XP, labs, accuracy), also for a student who belongs to no class. Names are abbreviated ("Inès M.") and no id or e-mail is exposed; the web client only asks for the class cohort. Restrict or drop `cohort=all` if names must not cross classes.
7. **Content review is global, not per class.** Any invited teacher account (even without a class) can move any mission through draft -> reviewed -> approved -> draft; reviewer names are visible to all teachers. The only legal cycle is enforced server-side (`409 illegal_transition` otherwise) and every change is audited.
8. **Students can join a class with its 6-character code** and the teacher has no remove/approve/rotate endpoint; the student's record is then visible to that teacher.
9. **Login lockout is per IP.** 60 failed logins from one address block correct logins from that address for 10 minutes (a whole classroom behind one NAT can lock itself out).
10. **Penalties are capped, so wrong answers stop costing XP once the penalties equal the points earned (R20-A-02, known design item).** After about 13 wrong answers on a 180-point mission the score sits at 0 and further wrong answers cost nothing more. The mission still completes at score 0 and still grants its fragment and the unlock progress, because fragments and exits depend on completion, not on score. Choice, decision and point steps give no partial-progress signal, so guessing can finish a mission without domain knowledge; the only brake is the answer rate limit (120/min/student). XP and the leaderboard are protected; knowledge-gated progression is not. Decide whether a floor on completion, an attempt cap or a score threshold for the fragment is wanted.
11. **Shared-NAT lockout and teacher status control (R20-A-09, R20-A-07).** The failed-login bucket is keyed on IP plus e-mail, so anyone behind the same school network can lock a classmate's sign-in for 10 minutes with 8 wrong guesses (item 9; deliberate trade-off against locking the owner out from elsewhere). Any teacher account (anyone holding the invite code) can review, approve and re-open (`approved` -> `draft`) any mission, including one they reviewed themselves; the status is global (item 7) and `approved` is not a scientific validation. Attribution and the `content_audit` table exist and illegal transitions are refused.
12. **Round 21 P3 items on the e-mail rule (R21-A-02, A-03, A-04).** (a) A sign-in miss or a registration with a non-ASCII e-mail scans the stored non-ASCII e-mails synchronously: about 20 ms more at 20 000 such accounts, about 270 ms at 200 000; the per-IP limits cap the abuse and a classroom database is far smaller. (b) The rule is NFC + trim + lower-case only: a zero-width character (for example a trailing U+200B) is accepted and makes an address that does not match the visible one; fullwidth, ligature and dotless-i look-alikes stay separate accounts; lower-casing can lengthen an address past the 200-character schema limit. No cross-login is possible. (c) `user.demo` is present on `GET /api/profile` only, not on `/api/me` or the login replies. Rows stored before the rule that share one normalised key can each still sign in with their own password (R21-A-01, fixed and tested; R22-A-01/02: a wrong password then costs one scrypt check per such row, about 32 ms each, and when two such rows have the same password the row whose e-mail equals the normalised key wins, otherwise the lowest rowid in current SQLite behaviour, which is not a guarantee; the API can no longer create such a collision); the development database holds none (46 users, no collision, no non-ASCII e-mail).
13. **Round 21 visual P3 items on the portfolio screenshots (V-06, V-08, V-09, V21-04 to V21-06).** Lab names and states differ between screens ("Hematology" vs "Hematology Lab", ACTIVE vs NOT STARTED, CLEARED vs ESCAPED) because they come from different payloads and presentation helpers; the disabled Submit button of screenshot 03 is low-contrast and the Submit of 04 has the colour of the error box; some sidebar items use a chevron instead of an icon; screenshot 08 shows 100 % lab accuracy next to 95 % for the competency of the same mission (the competency score is weighted by hints, which the screen does not say); screenshot 10 is cut mid-line at the bottom; the caption of 02 calls the Master Lab "playable" while the image shows it locked.
14. **Test infrastructure, one unexplained failure (round 21, second Playwright pass).** In one of the full passes of round 21 the three `production-bundle` tests failed with `ERR_CONNECTION_REFUSED` on ports 4173 and 4174 (the preview servers of the built bundle were gone at the end of the run) while the 408 other tests passed. It did not recur in the 4 full passes run afterwards (rounds 22 and 23; the preview servers stayed up, logged about every 2 s in `.ci-artifacts/local-2026-10-09-round21-22/watch.log`, `r21-failed-pass/watch.log` and `final-r23/watch.log`), and the project alone passed 3/3 (`r21-failed-pass/prod-only.log`). The cause was not established (no stop signal was recorded: the log that the Playwright configuration was meant to write pointed to a deleted session folder; it now writes to `webserver-exit.log` in the suite's temporary folder). Treat it as an open infrastructure observation, not as a product defect and not as a proven flake.

## Content (needs the human education/biomedical reviewer)

All keys, flags, hints, explanations and images are **unvalidated by a biomedical or pedagogical reviewer**; the release verdict stays ESCALATE for that reason alone. A consistency read (key vs. displayed values, units, ambiguity) was done by an AI assistant and its findings are listed in `docs/SCIENTIFIC_REVIEW_BACKLOG.md` (25 items, 1 provisional blocker). That backlog is an unsigned preparation document for the human reviewers, not a review, and `docs/FINAL_VALIDATION_REPORT.md` does not contain a list of content findings; it does not replace the review. All images are illustrative artwork and are labelled as such.

## Technical limits

- SQLite on a single node. Rate limits are in memory and per process. Several instances need a shared store and Postgres. Answers, mission start, unlock and content transitions re-read their state under the write lock, so two processes on one file are safe for those paths; the in-flight hint guard is per process, so with two processes one can reserve a hint on an attempt another process completes meanwhile; since round 17 that hint keeps its charge, its `hint_log` row and its place in the frozen result (hint penalty and no No Hint badge, consistently) and is still delivered, and only a hint whose attempt expired or moved to another step is refunded (see Round 17 notes).
- `TRUST_PROXY=<hops>` is only safe when the API port is reachable solely through that many proxies.
- The AI hint guard (`src/assistant.ts`) only filters answers that appear verbatim; it is a last line of defence, not a guarantee. With no `LAB_ASSISTANT_*` variables every hint is the faculty-written standard hint.
- Demo seeding (`seedDemo`) is not one transaction: a crash mid-seed can leave a partial demo dataset that is then reported as "already present". Delete the demo database and reseed.
- The shared demo teacher can be renamed or can add classes and content reviews until someone calls `POST /demo/reset` with the teacher token; the reset restores the name, the two seeded classes and the content reviews the demo teacher itself made (the append-only audit gets extra `[demo reset]` rows). Reviews made by other teachers survive a reset (round 10); a review is the demo teacher's when its reviewer label carries the demo teacher's id or, for reviews recorded before round 9, when the latest audit row for that mission names that account. Between resets the teacher guest is shared and editable by every visitor. Content reviews recorded before round 9 carry only the display name; new ones carry `Name (teacher #id)`.
- "Labs completed" counts the three standard labs (denominator 3); the Master Lab is never counted in that figure and appears only through its own badge and lab state.
- With `DEMO_MODE=1` the API listens on `127.0.0.1` only; the web client's default base URL is `http://localhost:3000`, which resolves to loopback in browsers (they retry IPv4 when `::1` refuses).
- The OpenAPI document describes routes, request bodies and the error statuses each route can return (400, 401, 403, 404, 405, 409, 413, 415, 422, 429), but no success-response schemas. `POST /missions/:id/start` answers 201 even when it resumes an existing attempt (`resumed: true` in the body).
- **Streak days follow UTC midnight**, not the learner's local day (no time zone is stored): a UTC+2 learner playing just after local midnight can see a streak of 1 for two consecutive local days.
- **Scale**: the leaderboard (about 4 queries per student, no rate limit) and class analytics (about 9 queries per student) are computed per request; at a few thousand students the leaderboard blocks the single-threaded server for roughly 100 ms. Statements are now prepared once, but the per-student queries remain. Fine for the demo class of 38; aggregate or cache before a large cohort.
- `NODE_ENV=test` multiplies the per-user answer/hint/start limits by 50 for the shared E2E guest: never run a public server with `NODE_ENV=test`.
- Stopping the server (SIGTERM) while an AI hint is being generated keeps the hint penalty without delivering the text (only with `LAB_ASSISTANT_*` configured); such a hint is counted but has no stored text, so it never appears in the list of earlier hints. **Superseded by R16-A-02 (see "A paid hint is persisted with its charge" below): the charge and the standard hint text are now one commit, so a hint interrupted while the assistant was generating keeps its standard text and lists it after a restart (verified by SIGKILL 500 ms into a 1.5 s assistant call at round 35, A35-005; this sentence was left stale until round 36, C36-001).**
- Hint text is stored with each hint since schema v6 (`hint_log.text`) and listed again after a reload as `step.hintsGiven`. Hints bought before that migration are shown again only when they were the faculty-written standard hint; an AI-written hint from that period cannot be recovered and is omitted (it still counts in the used-hints figure).
- "Hints" on Lab results and on the teacher's student header count the best attempts only (they match the ledger shown beside them); the teacher's attempt history lists every attempt.
- `language: 'fr'` is accepted by the profile API, but there is no French content or UI.
- WebKit/Safari is not tested; the "mobile" project is Chromium with an iPhone 13 device descriptor.
- No CI has run remotely: there is no Git remote in this workspace.
- The bearer token and the current attempt id live in `sessionStorage` (never `localStorage`), in `web/src/lib/api.ts` only; the SPA sets no Content-Security-Policy of its own.
- There is no URL routing: Back leaves the app, and a reload on Progress or Lab map returns to the dashboard (a mission or its result is restored from the server). Reloading in the middle of a matching or order mission keeps the penalty but clears the pairs entered.
- `POST /demo/reset` is not one transaction: another process could observe the demo student half-reset; the final state is always correct.
- The roster search folds case and accents by Unicode decomposition; letters without a canonical decomposition (Ł, Ø, Đ, ß, œ) are matched literally.
- The faculty "needs attention" label, lock reasons and all other explanatory copy come from the server; the client throws an explicit error when the server omits them instead of inventing text.

## Round 10 notes

- **Teacher-name uniqueness is a canonical-key comparison, not a guarantee against every lookalike.** Names are folded by NFKC, case, accents, whitespace/punctuation, invisible and bidi characters, and a small table of Cyrillic and Greek letters drawn like Latin ones. Confusables outside that table (other scripts, digit/letter swaps such as `0`/`o`, `1`/`l`) are not folded, and mixed-script names are not rejected because that would break legitimate names. Two teachers can therefore still pick names that look alike in some fonts; the review record keeps `(teacher #id)` as the unambiguous part. Existing duplicate names created before round 10 are left as they are (the rule applies on write; a teacher may always keep their current name). The check and the write are one `BEGIN IMMEDIATE` transaction rather than a UNIQUE index, because the canonical key is computed in application code and an index would break databases that already contain twins.
- **Display names containing `(teacher #number)`** are refused for every role (`400 validation_error`); names already stored are not rewritten. The pattern is matched after folding (any Unicode decimal digit, `№` as `#`, any bracket pair, look-alike letters). A name with nothing visible (only private-use, unassigned, invisible or stray combining characters) is refused the same way.
- **The demo reset can recreate a name twin on a database upgraded from before round 10.** `POST /demo/reset` restores the seeded name `Dr. Claire Moreau` without a uniqueness check. New databases cannot have a second teacher with that name (register and rename are refused with `409 name_taken`), but an older database may already contain a real teacher whose name reads the same; after a reset both accounts carry it (rename back by hand is refused with `409` while the twin exists). Review records stay unambiguous because they carry `(teacher #id)`. Rename the older teacher account to remove the twin.
- **Name keys are still not a full confusables table (round 11).** Capital and lower-case Cyrillic and Greek look-alikes of Latin letters are folded (including `Dr. Claire Мoreau`), as are Arabic harakat, tatweel and Hebrew niqqud, but Armenian, Cherokee and other scripts, and digit/letter swaps (`0`/`o`, `1`/`l`) are not. Cyrillic `й`, `ї`, `ў` are letters of their own and are not folded into `и`, `і`, `у`; `ё` counts as `е`.
- **`POST /demo/reset` on the teacher token is still unthrottled**, as it is the only mutating route without a budget (demo mode only).
- **R10-A-05 (not changed): the per-event `penaltyXp` (-10 per wrong answer, -15 per hint) is the nominal amount.** Once an attempt has already lost everything it can lose (the cap), `attempt.penaltyXp` can stay flat or even move the other way after one more wrong answer or hint, because the lost no-hint bonus leaves the budget. The cumulative figure is always right and equals the final ledger; only the delta shown next to one event can disagree. Fix later by returning the applied amount beside the nominal one.
- **R10-A-10 (not changed): while an AI hint is being generated** (up to the 4 s provider timeout, only with `LAB_ASSISTANT_*` configured) a reload shows `hintsUsed` and the -15 XP penalty but `hintsGiven: []`; the text appears after the commit. A second hint or an answer in that window answers `409 hint_in_progress`.
- **Demo-off refusal keys on the seed marker** (`users.is_demo_account`, schema v7), not on the e-mail domain. Databases seeded before v7 are backfilled by recognising the accounts on `@demo.escape-lab.app` whose password hash equals the demo teacher's (the seed hashes the published password once for all of them); a real account on that domain keeps working. New registrations on the domain are still refused (`reserved_email`).
- **`HOST=localhost` binds `127.0.0.1`** (IPv4 only), so Node 18 style clients and `curl 127.0.0.1` work; browsers resolve `localhost` to either family. Use `HOST=::1` for an IPv6-only loopback.
- The **dashboard `overall`** now counts the nine standard missions (same basis as the profile and teacher views); the Master Lab is extra.

## Round 12 notes

- **Teacher-name key is now ONE canonical key (R12-A-01).** Two names are "the same" exactly when their keys are equal, so the relation is transitive (a rename chain `м`arie -> `М`arie can no longer create a twin: round 11 compared two keys and accepted a match on either). A rename is refused only when ANOTHER teacher's key equals the new key. Databases that already contain twins are not rewritten: a twin may rename to any spelling inside its own name class (it creates no new clash) and may log in as before; moving away and coming back is subject to the normal rule. Because the Cyrillic and Greek tables now map capital and lower-case forms together (М/м, К/к, Т/т, Н/н, В/в), the key of such a name changed; stored names are untouched.
- **Greek N / nu is not case-folded (R12-A-01). Superseded in round 13: see "Round 13 notes" (case is now folded first, and eight Greek letters, not only N / nu, were affected).**
- **Latin look-alike classes (R12-A-03).** In the key only, `I`, `l`, `1` and `|` are one letter and `O` and `0` are one letter (so `Dr. CIaire Moreau` and `Dr. C1aire M0reau` are the reserved demo name). A single case-insensitive key cannot keep `i` and `l` apart while `I` = `i` (case) and `I` ~ `l` (shape), so the class also contains `i`: `Ian` ~ `Lan`, `Lina` ~ `Iina`, `Ali` ~ `Ail`, `Olga` ~ `0lga` collide for teachers (students may share names). Cyrillic `н` and `һ` also share a key. Still not folded: `rn`/`m`, the IPA block, Armenian, Cherokee and other scripts.
- **Teacher names that differ only by Vietnamese tone marks, an emoji/symbol or a space are the same name by design (R12-A-04)**, e.g. `Lê Thị Hà` / `Lê Thị Hạ`, `Dr. 🧬` / `Dr. 🧪`, `Li Wei` / `Liwei`. Accents on Latin letters, symbols and spacing are folded as an anti-spoofing measure; the second teacher gets `409 name_taken` with the message "Another teacher account already uses this name, or one that reads the same ... Choose another name." and must add a letter or word that does differ. Students may share names, so this affects teachers only.
- **Bidi controls are refused (R12-A-02).** U+202A-U+202E and U+2066-U+2069 are a `400 validation_error` in every display name and class name. The plain direction marks U+200E/U+200F and the joiners U+200C/U+200D stay allowed inside a name (Arabic, Hebrew, Persian and Indic scripts need them) but a name made only of them has nothing visible and is refused. Names stored before this round are not rewritten; the web client should still render names with bidi isolation (`<bdi>`).
- **Class names (R12-A-09, R12-C-10).** The "at least 2 visible characters" rule counts characters a person can see (zero-width, marks and spaces do not count) and every rejection carries `details`. A teacher cannot create a second class with the same name (case, spacing, compatibility forms and invisible characters ignored): `409 class_name_taken`. Classes created before this round are not renamed or merged.
- **Leaderboard `total` (R12-C-08).** `total` is the number of students of the cohort with XP in the window, identical for every viewer. A student without XP is not ranked and not listed; their `me` row has `rank = total + 1` (tied with the other unranked students) so a client cannot show "Showing 7 of 6"; it should not print a "N of M ranked" line for an unranked viewer.
- **Assistant hints (R12-A-05).** Control characters other than newline and tab and lone surrogates are removed from a provider hint before it is stored and returned, and the 400-character limit counts characters, not UTF-16 units.
- **Start-up and tooling (R12-A-07, R12-A-08).** A `DB_PATH` that is a directory, a non-SQLite file, under a file, unwritable, or written by a newer build ends with one line `Escape Lab API cannot start: cannot use the database at <path>: <reason>` and exit code 1. `db:backup` waits for a busy database (10 s) and a run that loses a race to the same target prints `Refusing to overwrite <path>` and exits 2; an empty output path prints a usage line and exits 1.

## Round 13 notes

- **Name keys fold case FIRST, then apply one lower-case table (R13-A-01).** Round 12 kept a CAPITAL table and a LOWER table, and eight Greek letters (`Β Ε Ζ Η Μ Ν Τ Υ`) were in the first but not the second (the round-12 text claimed `N` / nu was the only one), so `ελένη παπαδοπούλου` and `ΕΛΕΝΗ ΠΑΠΑΔΟΠΟΥΛΟΥ` could be registered next to `Ελένη Παπαδοπούλου`. Now the key of a capital and of its lower-case form is equal in every script (a test scans every cased Unicode character, including the polytonic letters with iota subscript). Accepted, documented residual: the lower-case Greek letters take the Latin letter their capital looks like (`β`->`b`, `ε`->`e`, `ζ`->`z`, `η`->`h`, `μ`->`m`, `ν`->`n`, `τ`->`t`, `υ`->`y`), so lower-case `ν` no longer reads as a Latin `v` and `υ` no longer as a `u` (`νina` is `Nina`, not `vina`); a teacher can still register a Latin look-alike of a Greek name only through the letters in that table. Keys of stored names change; stored names are not rewritten, and a teacher inside an existing twin group keeps the right to rename within it.
- **Reviewer suffix (R13-A-04).** A name containing `teacher` followed by `#`, `♯` or `№` and something that reads as a number (Unicode digits, or the look-alike letters `I l | O`: `#1O`, `#l0`) is refused (`400 validation_error`), with or without brackets, so `Eve (teacher #10` and `Teacher #5` are refused too. `Teacher`, `Teacher Smith`, `Teacher #Oliver` and `Room #5` stay allowed. `teacher No.10` (letters, no sign) is not matched. U+061C (Arabic letter mark) is added to the refused bidi controls. Stored names are not rewritten.
- **AI-hint answer guard (R13-A-02, R13-A-03).** Text from the assistant is dropped (the faculty hint is delivered instead, same penalty) when it contains a bidirectional control, "the answer/option/choice is", or the correct option's label compared through a skeleton on both sides (NFKC, zero-width / soft hyphen / format characters removed, case and accents folded, Cyrillic and Greek look-alikes mapped, then only letters and digits compared). A split, spaced, NBSP, newline, punctuated or reversed-under-override variant of the label is caught. Unchanged semantics: only the WHOLE label counts (a hint that mentions a word of it, or a lab value, is fine), labels of three letters or fewer are not guarded, and only choice and decision steps have a label; hints are not checked against other steps or against numeric answers. The 400-character limit is counted in code points by one shared helper for the Anthropic provider and `Game`.
- **Passwords (R13-A-08).** New passwords are hashed as NFC. Login tries the submitted string as typed (so every hash written before round 13 keeps working), then its NFC form (so an NFD login of an NFC registration succeeds). Work depends only on the submitted string (one scrypt for an already-NFC password, two otherwise) and not on whether the account exists. A password registered in NFD with an old build still needs the NFD form (or can be reset by re-registering; there is no password reset).
- **Start-up and file modes (R13-A-07).** A database file that is not writable by its owner (for example `chmod 444`) is never changed: start-up logs one warning when others can read it and carries on (superseded in round 14: such a file is now refused, see "Round 14 notes"). A database written by a newer build is refused before the journal mode is switched or any mode is changed. Modes are only ever narrowed (to at most 0600).
- **Class names (R13-A-10).** `409 class_name_taken` carries `details` like the other rejections. Class names are folded with their own, weaker key: case (ß/SS, final sigma), spacing, invisible characters, compatibility forms and Cyrillic/Greek look-alikes are ignored, while punctuation, accents, digits and the shapes `I l 1 | O 0` stay significant (`Section 1.2` / `Section 12`, `L1` / `LI`, `Year 1` / `Year I` are different classes). The person-name key was NOT used for classes because it ignores punctuation and merges `I l 1 |` and `O 0`.
- **Leaderboard initials (R13-B-03, R13-C-04).** The abbreviated name uses the first grapheme cluster (an emoji sequence, a flag, a letter with its marks) of the first visible letter-like character of the last word; invisible characters, joiners, direction marks, leading combining marks and punctuation are skipped, `ß` gives `S` and the digraph `dž` gives `D`. A last word with no such character gives the first name alone, without a trailing dot.
- **Student detail (R13-C-08).** `GET /api/classes/{id}/students/{studentId}` adds `historyTotal`, the integer number of all completed attempts (at least `history.length`; `history` is still the latest 20). CORS responses carry `Access-Control-Expose-Headers: Retry-After`, so a browser client can read the wait on a 429.
- **Leaderboard copy for an empty class (R13-B-02, R13-C-02).** "The class leaderboard appears when your learning group is set up" is client copy (`web/src/pages/progress.tsx`); the API already distinguishes `cohortAvailable: false` (no class) from `cohortAvailable: true, total: 0` (a class where nobody has XP yet). Not changed on the server.
- **Not changed (R13-A-05).** The `I l 1 |` merge collides real first names (`Maria` ~ `Marla`, `Kari` ~ `Karl`, `Lisa` ~ `Ilsa`; about 0.3% of a dictionary of 1308 names). The answer is a clear `409 name_taken`; it is a deliberate anti-spoofing trade-off, since one key per name cannot keep `i` and `l` apart while `I` = `i` and `I` ~ `l`.
- **Not changed (R13-A-06).** SQLite allows one writer. If another process holds the write lock for more than the 5 s busy timeout, requests that need the lock answer `500 internal_error` after 5-10 s (no `503`/`Retry-After`). It needs a second process on the same file (backup or a second server) and is documented as a multi-process limit.
- **Not changed (R13-A-10, performance).** The teacher-name check recomputes the keys of all other teachers inside the write lock (about 240 ms at 5000 teachers).
- **Not changed (R13-A-09).** The progress panel's "N of M ranked" line and empty-state copy are frontend work.

## Round 14 notes

- **Stray U+0345 (R14-A-01).** U+0345 COMBINING GREEK YPOGEGRAMMENI is the only combining mark with a case mapping (its upper case is the letter Ι), so the round-13 "fold case first" order turned a stray one into the letter `i` and `Dr. Claire Moreau` + U+0345 registered as a new teacher. It is now dropped before any case fold in the person-name key and in the class-name key. A U+0345 that follows α, η or ω is composed by NFKC into the iota-subscript letter (ᾳ) and stays equivalent to `αι` / `ΑΙ` (ᾀ = ἈΙ); a U+0345 anywhere else (after a Latin letter, a space, a digit, or a Greek letter that cannot carry it) is dropped like any stray mark. A test appends every Mn / Mc / Me code point to a Latin name and requires an unchanged key; there is no exception. One deliberate consequence: the round-13 "every cased character has the same key in both cases" scan skips U+0345 (the mark and the letter Ι are not one name).
- **Final sigma (R14-A-07).** `ς` and `σ` are one letter in the key, so a Greek name ending in sigma no longer depends on spacing (`Νίκος Ζhg` = `ΝίκοςΖhg`, `ΣΣ` = `Σ<U+3164>Σ`). Stored names are not rewritten.
- **Read-only database (R14-A-02).** Start-up now performs one write inside `BEGIN IMMEDIATE` ... `ROLLBACK` (`user_version` set to its own value, nothing committed). A database file the process cannot write (mode 0444 / 0400, read-only mount) ends start-up with one line and exit 1; the file is not touched. `db:check` still opens a database read-only and works on such a file. The old advice "consider chmod 400" is gone; the warning left for a root-owned 0444 file says chmod 600.
- **Assistant hints name the option by position (R14-A-03).** The learner sees choice and decision options as a lettered list by position (A, B, C ...), and the provider is now shown the same letters (default decisions included). The guard drops a hint that names the correct option by that letter, number or ordinal in English or French ("Option C", "C is correct", "Choose C", "Go with C", "Answer: C", "It is C", "(C)", "the third option", "the 3rd choice", "option 3", "option three", "la troisième option", "Letter C"), case-insensitively, with fullwidth forms, accents, look-alike letters, hidden characters and punctuation between the words. The article "a" is only read as the letter A when it is a capital or sits right after option / choice / answer / letter and ends its clause. Hints about other options, the word "option" alone, "vitamin C", "C-reactive protein" and the faculty hints of every step pass. The id of a decision option that is a word (`accept`, `alert`) is NOT guarded, only its position and label. Elimination ("everything except A, B and D is wrong") and clinical phrasings that point at the option without naming it are not detected.
- **Not changed (R14-A-04).** A correct label written with digits or look-alikes (`1ron`, `Ir0n`), reversed, or in IPA / small-cap / Armenian / Cherokee homoglyphs still passes the guard. It is a last line of defence, not a guarantee; the system prompt and the faculty fallback are the main protection.
- **Not changed (R14-A-06).** The "answer / option / choice is" phrase check also rejects some harmless hints ("The third option is not consistent with..."). The fallback to the standard hint (same penalty) is the safe failure.
- **Blank provider hint (R14-A-05).** A provider text with no visible letter, digit or emoji (zero-width, U+3164, Braille blank, combining marks only, `.` or `...`) counts as empty: source `standard`, faculty hint delivered.
- **Passwords (R14-A-08).** The 10-character minimum is counted after NFC (`e` + U+0301 five times is five characters) and a password made only of whitespace is a `400 validation_error`; the check runs before the registration rate limit. Login is unchanged and the demo password still works.
- **HEAD (R14-A-10).** `HEAD` on any `GET` route (`/api/health`, `/api/openapi.json`, authenticated routes with their guards) answers like `GET` with the same status and headers and no body. `Allow` on a 405 lists `HEAD` next to `GET`; routes that are not `GET` still answer `405` to `HEAD`. Nothing is added to OpenAPI.
- **Leaderboard initials (R14-C-01, R14-A-09).** Only a letter, number or emoji can be the initial: the Hangul fillers (U+3164, U+115F, U+1160, U+FFA0), symbols such as `™` / `©` / `®` (unless followed by the emoji selector U+FE0F), modifier letters and invisible characters are skipped, and a first word with nothing visible is ignored. `ŉ` gives `N`. Unchanged and by design: a name WITHOUT a space (`王小明`, `สมชายใจดี`, `JeanDupont`, `Ann<ZWSP>Lee`) has no last word and is shown in full to classmates; the abbreviation is a space-based rule and cannot split such a name. Students who want to hide their full name should register a first name and an initial.
- **OpenAPI (R14-A-11).** The class-name rule is spelled out (case, ß / SS, final sigma, whitespace length, invisible characters, a stray U+0345, compatibility forms and Cyrillic / Greek look-alikes ignored; punctuation, accents, digits and the shapes I l 1 | and O 0 significant), and every `429` references a `RateLimited` response that declares the `Retry-After` header (and the `Access-Control-Expose-Headers` note).

## Round 15 notes

- **Greek lunate sigma (R15-A-01).** U+03F2 / U+03F9, drawn exactly like a Latin c, were turned into sigma by NFKC before the look-alike table ran, so `Dr. Ϲlaire Moreau` registered next to the reserved demo teacher. They are now mapped to `c` / `C` before the first NFKC in the person-name key, the class-name key, the skeleton and the text the AI-hint guard reads. A test now checks that EVERY entry of the look-alike table reaches its Latin target through the whole pipeline (a scan of the table against NFKC / NFKD of its own entries found no other dead entry). Stored names are not rewritten.
- **Iota subscript (R15-A-02).** U+0345, and the iota subscript inside the precomposed letters (ᾀ-ᾯ, ᾳ, ῃ, ῳ, ᾲ ... ῼ), is dropped ALWAYS from the name and class keys, before any case fold. `Μαρία Παπαδοπούλου` / `Μαρίᾳ Παπαδοπούλου` and `Ελένη` / `Ελένῃ` are one name. Accepted loss, which replaces the round-14 behaviour: a subscript is an accent like any other, so `ᾀ` is no longer the same name as `ἈΙ`, nor `ᾳ` as `ΑΙ` (alpha + iota); a teacher whose name contains the diphthong spelled out and one who writes it with the subscript are two names. The tests of round 13 (cased-character scan) and round 14 (`ᾀ == ἈΙ`) that encoded the old equivalence were changed accordingly. The scan "every cased character has equal keys in both cases" compares only the lower-case form for these letters, because their upper case expands to two letters.
- **AI-hint position guard (R15-A-03).** Only active when `LAB_ASSISTANT_*` is set. The closed list now also drops: the bare letter or number alone (`C`, `**C**`, `"C"`, `C)`, `3`, `#3`), a capital letter that opens a clause and is closed by a mark (`C.`, `C:`, `C, definitely`; not `C. difficile`), a pointing word before a letter that ends its clause (`Look at C`, `Consider C`, `Focus on C`, `I would say C`, `Hint: C`, `Tick / Mark / Circle / Check / Click / Tap / Press C`, French `Regardez C`), `C'est C`, spaced or glued letters (`O p t i o n C`, `OptionC`, `A n s w e r : C`), Roman numerals from II up (`Option III`, `option iii`; `Option I` is the pronoun and is not guarded), a number that ends its clause after a choosing word or a pronoun (`Choose 3`, `Go with 3`, `It is 3`, `No. 3`; `Choose 3 markers` and `It is 3 mg/dL` pass), and an ordinal ending its clause (`Go with the last`, `Choose the last`, `Go with the first.`). No faculty-written hint, re-check, prompt or context passes through it wrongly (a test scans all of them), and `vitamin C`, `C-reactive protein`, `37 °C`, `step 3`, `Option` alone, `Take 3 samples` and the article `a` pass. It remains a CLOSED HEURISTIC, not a guarantee: still not detected are, for example, `go w/ C`, `C is the one`, `C is not wrong`, `C'est la C`, letters of other scripts or exotic numerals (Cherokee, Gothic ...), a bare ordinal (`the third`), elimination and clinical hints that point at the option without naming it. A hint the guard misses is delivered for the hint price; the system prompt (never state the answer, never give a letter) and the faculty fallback are the main protection. A false positive only costs the learner the AI text: the faculty hint is delivered instead.
- **HEAD is safe (R15-A-04).** A `HEAD` runs the GET handler with SQLite in `query_only` mode and without the lazy writes of read paths (closing timed-out attempts, catching up badges), so it never changes a row. A `HEAD` on an overdue attempt reports `status: in_progress` (with `expired: true` and `remainingSec: 0`, as a GET does) until a GET or any other request of that student closes it; on `/result` of an overdue attempt a HEAD answers 409 `attempt_in_progress` where a GET answers 409 `time_expired`. Status codes and headers of all other pairs are unchanged.
- **Guard performance (R15-A-06).** `leaksAnswer` analyses at most 4000 code points and treats a longer text as a leak (every caller already rejects more than 400 first, and the length test now runs before the substance test); the neighbour lookups of the position guard look at a window of three characters, so a 1 MB text is answered in milliseconds instead of minutes.
- **Passwords (R15-A-07).** A new password needs at least 6 visible characters after NFC (whitespace, zero-width, format, default-ignorable, private-use, unassigned and the filler characters U+3164, U+115F, U+1160, U+FFA0, U+2800 do not count, nor combining marks that follow no visible character) on top of the 10-character minimum, which is now counted ONLY by the handler on the NFC form (the schema no longer has a `minLength`, so `5 x U+0344` gets the visible-characters message instead of a raw-length one). `a` followed by 9 combining marks, or a password such as `abcdef` plus invisible characters, is still valid (weak but valid); the rule is deliberately conservative. Demo passwords and every account created before round 15 are unaffected (login is unchanged).
- **Not changed (R15-A-05).** (a) The start-up write probe waits up to the 5 s busy timeout when another process holds the write lock for longer, then ends start-up with `database is locked` on a healthy database; (b) two exotic read-only layouts (a rollback-journal database with mode 0444; a writable main file with read-only `-wal` / `-shm` sidecars) end start-up with the raw SQLite sentence "attempt to write a readonly database" instead of the friendly one; (c) a roughly 0.25% first-start race on a brand-new database file started by several processes at once. None risks data; all need a second process or an unusual file layout on the same database.

## Round 16 notes

- **Lone surrogates (R16-A-01).** A name or class name (every field with the `\S` pattern) containing an unpaired UTF-16 surrogate (JSON `"\ud800"`) is now a `400 validation_error`. SQLite stores such a character as U+FFFD while the comparison key used to be computed on the submitted text, so two creates both succeeded and the create response echoed a different string than every later read. As defence in depth, every key in `names.ts` is computed on `toWellFormed()` text and `createAccount` / `updateProfile` / `createClass` store (and echo) the well-formed name. Other free-text fields (`program`, `studyLevel`) are unchanged: the database turns a lone surrogate into U+FFFD there and nothing compares them.
- **A paid hint is persisted with its charge (R16-A-02).** The hint-log row is now inserted in the same transaction that counts the hint (`source: standard`, text = the faculty hint of that level). When the assistant answers and passes the guard, the row is updated to `source: assistant` and its text; when it fails, times out or is refused the learner already has the standard hint. A process stop between the charge and the delivery therefore never costs 15 XP and the no-hint bonus for text that cannot be read: after a restart `step.hintsGiven` lists the standard hint. This replaces the R10-A-10 display lag below: while an AI hint is being generated a reload now shows the faculty hint (`source: standard`) and, once the provider has answered, the assistant text replaces it (one level, one text at a time; never two entries). The refund paths (expiry or step change during the call) delete the row with the refund.
- **`readOnlyRequest` (R16-A-04).** The flag and `PRAGMA query_only` are set inside the `try`, restored in `finally` whatever fails, and `query_only = OFF` is retried up to three times. A nested call leaves the outer one in charge. Latent defect only; nothing in the wild was observed.
- **Concurrent demo resets (R16-A-05).** The student reset runs its delete and replay inside one `BEGIN IMMEDIATE` transaction (`tx()` now uses a savepoint when a transaction is already open), so two resets from two processes queue behind each other (up to the 5 s busy timeout) and both answer 200 with the canonical state, instead of one answering 403 / 404 / 409 from inside the replay. The replay only awaits resolved promises (the standard hint provider), so nothing else on the event loop runs inside the transaction. A reset that fails half way is rolled back as a whole.
- **AI-hint guard: one more rule, still a heuristic (R16-A-03).** Only active when `LAB_ASSISTANT_*` is configured (AI hints are OFF otherwise: every hint is the faculty text). The closed list was not extended. A new, deliberately high-recall rule drops a provider hint for a choice / decision step when it contains the correct option's letter as a standalone CAPITAL (`Try C`, `Stick with C.`, `C seems plausible`, `**C**`, a Cyrillic / Greek / squared look-alike capital), after clinical vocabulary is removed (vitamin / hepatitis / protein C, `C-reactive`, `B-cell`, `D dimer`, `37 °C`, `type A / B / AB`, `group A / B`, `Factor C`, `B cells`, `C. difficile`, `type C hepatitis`). The article `A` counts only when it is not followed by an ordinary lower-case word (`A low MCV` passes, `A seems plausible` is dropped). Measured: 0 refusals on the 66 faculty hints / re-checks / cases / prompts of the 19 choice and decision steps and 0 of 360 cross-step faculty hints (the explanations name the answer by design and are never sent through the guard). On a generated corpus of 465 benign sentences it adds 41 false positives (mostly `Tube B`, `Sample C`, `The D antigen`, `A or B?`, `group C`); the cost of a false positive is the faculty hint at the same price. Still not caught: lower-case letters, numbers and ordinals beyond the closed list, other languages' phrasings, any text the model words around a letter without a capital. The guard remains a last line of defence, not a guarantee.
- **Header block above 16 KB (R16-A-07).** Node answers `431 Request Header Fields Too Large` itself (for example an Authorization value of 20,000 characters), before the application runs: no body and no JSON error envelope. It is now declared once in OpenAPI (`components.responses.HeaderTooLarge`) and referenced by every operation. The UI never produces it.
- **Not changed (R16-A-06).** The Greek lunate sigma (U+03F2 / U+03F9) is a Latin `c` in the key since round 15, so `Σωκράτης` and `Ϲωκράτης` are two different teacher names. Accepted: the lunate form is a spoofing vector for Latin names, and the two glyphs are drawn differently in most fonts.

## Round 17 notes

- **Hint finishing after the attempt was completed elsewhere (R17-A-01).** With two processes on one database, a hint reserved before another process completed the attempt used to be refunded in the counters (`hints_total`, `step_results.hints`, `hint_log`) while the frozen `result_json` kept `hintsUsed: 1` and the -15 XP, and the No Hint badge was granted (563 of 4,658 attempts in a 3-process stress). It is documented, not declared per operation: the description of the shared `components.responses.HeaderTooLarge` response says so. The UI never produces it.
- **Not changed (R17-A-05).** Resetting a demo student that has about 4,000 attempts / 400,000 answer-log rows holds the write lock and the event loop for about 2.5 s (a normal reset takes 6-16 ms; another process waiting for the write lock waits as long, up to the 5 s busy timeout). Not a regression (the old reset deleted the same rows synchronously) and unreachable in the demo, where the demo student has a handful of attempts.
